# Lua interface (buffered model responses)

Run with `cargo run -p artist -- -p "first prompt" "second prompt" --config path/to/config.lua` (or repeat `-p`). Prompts run in order using one conversation. Use `--model model-id` to select a model or `--list-models` to list configured/discovered IDs. No provider is configured by default. See `configs/mock-model.lua` for a working configuration for the local mock API.

- `artist.provider({ name = "my-provider", models = {"model-a", "model-b"}, default_model = "model-a", adapter = "chat_completions", endpoint = "https://.../v1/chat/completions", auth = { bearer_env = "API_KEY" }, headers = { ["x-custom"] = "value" }, options = { temperature = 0.5 } })` registers one provider with multiple model IDs. `default_model` is optional if there is just one configured ID; otherwise choose with `--model`. `endpoint` defaults to OpenAI's endpoint. `auth.bearer_env` is resolved when making a request; header values may also be zero-argument Lua functions evaluated per request. See `configs/mock-model.lua` and `configs/opencode-go.lua`.
- Add `discover = { endpoint = "https://.../v1/models", filter = function(id) return ... end }` for optional OpenAI-style `GET /models` discovery (`data[].id`). `--list-models` fetches it and combines it with `models`; normal prompts do not make discovery requests. `filter` is optional. Discovery does not prove that a model supports Chat Completions or tool calls: OpenCode Go's catalog includes models for Responses and Messages too. Use a filter or a hardcoded list to avoid offering incompatible models. Discovery pagination is not yet supported. For discovery-only providers, supply `default_model` or `--model`; no implicit first-model selection.
- `artist.provider({ name = "my-provider", models = {"model-id"}, request = function(context, tools, model_id) ... end, response = function(status, headers, body) ... end })` is the generic HTTP escape hatch and registers the provider. `request` returns `{url, method?, headers?, body, timeout?}`. Rust serializes `body` as JSON and sends it with `reqwest`. `response` receives a Rust-decoded JSON table and returns an array of `ModelEvent` tables (with `type` fields such as `text_delta`, `tool_call_start`, `tool_call_arguments_delta`, `tool_call_end`, `finished`). Non-2xx responses are passed to `response` too.
- `artist.model({...})` remains as a compatibility alias for a single-model provider.
- `artist.register_tool({name, description, parameters, execute = function(args, ctx) ... end})` registers a tool. `parameters` is JSON Schema; `ctx.cwd` is the current working directory. `execute` returns a string or `{text, is_error?}` and may call async native functions.
- Bundled `src/default.lua` defines and registers each built-in tool's schema individually. Its callbacks run the Rust implementations through `artist.native.execute(name, args, cwd)`. User tools use the same `artist.register_tool` API. `artist.unregister_tool("write")` removes a registered tool, so it is neither advertised nor dispatched; an unknown name is an error.
- `artist.set_system_prompt(text_or_function)` replaces the base prompt; `artist.append_system_prompt(text_or_function)` appends a section. Functions receive `{model_name, cwd}`. Bundled `src/default.lua` sets the default prompt, and user config runs afterward. The composed prompt is stored once for the conversation.
- `artist.select_context(function(conversation) ... end)` optionally returns a `ContextSelection` table before each request; fields include `include_system_prompt`, `included_entries`, and `included_blocks`. Omit it to include all history. Selection does not mutate the stored conversation.
- `artist.json.decode(string)` and `artist.json.encode(value)` use Rust's JSON implementation. JSON null is `artist.json.null` in Lua, not `nil`.

The first slice uses complete JSON responses; model streaming decoding is not wired yet. `artist -p` writes newline-delimited JSON events to stdout. Lua config files are trusted code.
